# 6.22 启动器全分支同步问题修复

## 背景

启动器（launcher）需要从远程 Git 服务器（`https://denghuominghui.top/api/git/repo.git`）获取仓库的所有分支，
分别克隆/更新到本地。涉及主仓库（normal repo，有工作目录）和备份仓库（bare repo，纯对象存储）。

## 问题列表

### 问题 1：`syncBranches` 用 `git branch -r` 判断远程分支，导致误删本地分支

**表现**：
```
[syncBranches] 删除本地分支: 0.2.3 - 远程已删除
[syncBranches] 跳过当前分支 main（远程已删除但保留本地）
```

远程明明有 `0.2.3` 和 `main`，但代码认为它们都被删了。

**根因**：
`syncBranches` 使用 `git branch -r`（列出本地缓存的远程跟踪引用）来判断远程有哪些分支。
如果之前 `git fetch --prune origin` 因为网络波动、认证问题等导致 remote 返回空 refs 列表，
`--prune` 会清空本地缓存的远程跟踪引用（`refs/remotes/origin/*`），
此时 `git branch -r` 返回空列表，所有本地分支都被判定为"远程已删除"。

**修复**：
改用 `git ls-remote --heads <remoteURL>` 直接从服务器查询远程分支列表，
不依赖本地缓存的 `branch -r`。

### 问题 2：`syncBranches` 不返回 error，错误静默忽略

**表现**：
删除/创建分支失败时只 `Logf` 不返回 error，调用方永远不知道。

**修复**：
`syncBranches` 改为返回 `error`（返回第一个错误，但继续处理剩余分支）。

### 问题 3：`PullUpdates` 中备份仓库不同步分支

**表现**：
备份仓库只 `git fetch --prune origin`，不调用 `syncBranches`，
备份库的分支引用可能过时。

**修复**：
备份仓库也进行分支同步（但注意 bare repo 没有 `origin/xxx` 形式的远程跟踪引用，
所以不能直接调 `syncBranches`，见问题 4）。

### 问题 4：备份仓库（bare repo）缺少 `fetch` refspec

**表现**：
备份仓库 config 文件：
```
[remote "origin"]
    url = https://denghuominghui.top/api/git/repo.git
    ← fetch 行缺失！
```

正常 bare clone 的配置：
```
[remote "origin"]
    url = ...
    fetch = +refs/heads/*:refs/heads/*
```

没有 `fetch` 行，`git fetch --prune origin` 只更新 `HEAD`，不会拉取 `refs/heads/*` 下的其他分支。

**根因**：
`ensureBackupRepo`（`updater.go:582`）在备份仓库丢失时用 `git clone --bare <projectDir> <backupDir>`
从本地重建。如果此时主仓库也缺少某些分支（被问题 1 误删），重建的备份也缺少这些分支。
后续 remote URL 被更改后，`fetch` refspec 在这个过程中丢失。

**修复**：
- `PullUpdates` 中备份仓库 fetch 前执行 `git config remote.origin.fetch "+refs/heads/*:refs/heads/*"`
- `cloneProject` 中备份仓库克隆后立即确保 refspec 存在

### 问题 5：`cloneProject` 只 checkout 默认分支

**表现**：
`git clone <url>` 默认只 checkout 默认分支（如 `main`），其他分支虽然会拉取对象，
但不会创建本地分支。

**修复**：
- 改用 `git clone --no-checkout`，不 checkout 任何分支
- 用 `git ls-remote --heads <url>` 查询所有远程分支
- 遍历所有远程分支，逐一 `git branch --track <name> origin/<name>` 创建本地跟踪分支
- checkout 默认分支

### 问题 6：`syncBranches` 只创建缺失分支，不更新已有分支

**表现**：
已有本地分支不会被更新到远程最新提交。

**修复**：
在 `syncBranches` 中新增强制更新逻辑：对非当前分支执行 `git branch -f <name> origin/<name>`。

### 问题 7：`syncBranches` 日志不清晰

**表现**：
用户看不到分支同步的具体操作。

**修复**：
添加 "分支已同步" 日志，记录每个分支的处理结果。

## 备份仓库数据流

```
cloneProject (首次):
  git clone --bare <remoteURL> <backupDir>    → 从远程克隆全部 refs/heads/*
  git config remote.origin.fetch "+refs/heads/*:refs/heads/*"  → 确保 refspec

PullUpdates (每次更新):
  ensureBackupRepo → 如果备份不存在，从本地 clone --bare（潜在问题源）
  git config remote.origin.fetch "+refs/heads/*:refs/heads/*"  → 确保 refspec
  git fetch --prune origin    → 拉取所有 refs/heads/* 更新
```

注意：备份仓库是 bare repo，refspec 为 `+refs/heads/*:refs/heads/*`，
远程分支直接映射为本地 `refs/heads/*`，不存在 `origin/xxx` 形式的远程跟踪引用。
所以备份仓库**不需要**调用 `syncBranches`（它设计上依赖 `origin/xxx` 引用）。

## 分支图面板不显示其他分支

**根因**：
分支图面板（`GitDualGraph` in `app.go:474`）使用 `backupDir`（备份仓库）的数据渲染。
备份仓库缺少 `0.2.3` 分支（见问题 4），所以图面板只显示 `main`。

`GitBranches()` 虽然从主仓库获取分支列表，但图面板的 commit 拓扑来自备份仓库。

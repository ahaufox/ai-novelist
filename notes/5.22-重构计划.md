## 核心思路

去掉 `tool_requests` 独立字典和前端 `currentToolRequest` / `toolRequestVisible` 中间状态。
**完全用消息链的完整性来推导"哪个工具待审批"**。

### 数据库 data 结构（简化后）

```json
{
  "messages": [
    { "id": "m1", "role": "user", "content": "...", "parent_id": "__root__" },
    { "id": "m2", "role": "assistant", "content": "...",
      "tool_calls": [{ "id": "call_a", "function": { "name": "edit", "arguments": "..." } }]
    },
    { "id": "m3", "role": "tool", "content": "执行结果",
      "tool_call_id": "call_a", "parent_id": "m2" }
    // call_b 没有 tool 消息 → 待审批
  ],
  "active_leaf": "m3",
  "summaries": []
}
```

### 进度推导逻辑（前后端共享）

```
最后一个 assistant 消息的 tool_calls[]
    ↓ 逐个检查 tool_call_id
在 messages[] 中找 role==tool 且 tool_call_id 匹配的消息
    ↓
找到 → 该工具已处理 ✅
没找到 → 该工具待审批 ❌ → 显示面板
```

## 数据流

```
用户发送消息
  │
  ▼
POST /api/chat2/message → AI 流式响应
  │                       └─ assistant 消息含 tool_calls
  │                         直接存 messages[]，不再写 tool_requests
  │
  ▼
前端收到 state_update → setMessagesTree（纯搬运）
  │
  ▼
ToolRequestPanel 用 getPendingToolCall(messages) 推导第一个待审批工具
  │
  ▼
用户点击 [批准/取消]
  │
  ▼
POST /api/chat2/function_calling
  body: { tool_call_id, approved, user_diff, final_content }
  │
  ▼
后端：
  1. 从请求体中取 tool_name + arguments（从消息链查找）
  2. 执行/拒绝工具
  3. 创建 tool 消息追加到 messages[]
  4. 检查 _get_pending_tool_calls()：
     ├── 还有待审批 → 只返回 state_update（前端自动显示下一个）
     └── 全部完成 → 继续 AI 对话
```

## 核心函数

### 后端 `_get_pending_tool_calls()`
```python
def _get_pending_tool_calls(thread_id: str) -> list[dict]:
    history = storage.get_active_path(thread_id)
    # 找最后一个 assistant 消息
    last_assistant = None
    for msg in reversed(history):
        if msg.get("role") == "assistant" and msg.get("tool_calls"):
            last_assistant = msg
            break
    if not last_assistant:
        return []
    # 收集已有的 tool_call_id
    existing_tool_ids = {
        m["tool_call_id"]
        for m in history
        if m.get("role") == "tool" and m.get("tool_call_id")
    }
    # 返回没有对应 tool 消息的 tool_calls
    return [tc for tc in last_assistant["tool_calls"]
            if tc.get("id") and tc["id"] not in existing_tool_ids]
```

**"下一个待审批工具"由后端全权计算，前端只读不推导**  
  
数据流：  
后端 get_full_tree()  
  └── _get_pending_tool_calls() 计算 next_pending_tool  
      ↓  
state_update / history / summarize 都带着 next_pending_tool  
      ↓  
前端 setMessagesTree() 原样存入 nextPendingTool  
      ↓  
ToolRequestPanel 读 nextPendingTool，直接显示

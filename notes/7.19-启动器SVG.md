下面是启动器中 Git 分支图 SVG 绘制的完整代码逻辑讲解，分 **Go 端数据解析** 和 **React 前端 SVG 渲染** 两层。

---

## 整体架构

```
git log --graph --all  (原始 ASCII 输出)
        │
        ▼
  Go 端解析 → GraphOutput { nodes[], segments[] }  (结构化数据)
        │
        ▼
  React 前端 GitGraphCanvas.tsx → SVG 渲染
```

## 一、Go 后端：数据解析层 [`launcher/internal/gitman/gitman.go`](launcher/internal/gitman/gitman.go:474)

### 1. 获取原始 graph 输出（第 476-486 行）

执行两条 git 命令：

```go
git log --graph --all --format=%H --max-count=500   // 获取 ASCII 分支拓扑
git log --all --format=%H|%P|%s|%an|%aI|%D          // 获取 commit 详情
```

### 2. 逐行扫描 ASCII graph（第 506-573 行）

`git log --graph` 的输出格式是每行一个 commit，图形前缀 + SHA。例如：

```
*   a1b2c3d
|\  4e5f6a7
| * 8b9c0d1
| * 2a3b4c5
|/
*   d6e7f8g
```

**扫描规则**（第 520-571 行）：

- **偶数位置**（`pos % 2 == 0`）= lane 指示符
  - `|` → 添加竖线线段 [`SegData`](launcher/internal/gitman/gitman.go:346) `{type: "vline"}`
  - `*` + 有效 SHA → 创建 [`NodeData`](launcher/internal/gitman/gitman.go:325)（commit 节点，记录 `row`、`lane`、SHA 等）
- **奇数位置**（`pos % 2 == 1`）= 连接线
  - `\` → 添加 fork 线段 `{type: "fork"}`（从左 lane 到右 lane）
  - `/` → 添加 merge 线段 `{type: "merge"}`（从右 lane 到左 lane）

### 3. 补充缺失竖线（第 576-648 行）

由于 `git log --graph` 在某些场景下会省略连续行的 `|`，代码会二次扫描，收集每个 lane 上所有活动行号，然后补充漏掉的 vline 线段。

### 4. 颜色分配（第 650-713 行）

- 10 色调色板（第 293-304 行）：
  `橙、绿、蓝、粉、紫、青、琥珀、黄绿、黄、深橙`
- [`hashToColor()`](launcher/internal/gitman/gitman.go:306) 函数——对字符串（分支名或 `"lane-N"`）做 DJB2 哈希，取模映射到调色板
- 每个 lane 优先用分支名作为种子，保证同一分支始终同色
- 线段颜色取自来源 lane（`FromLane`）

### 5. 线性链修复 [`fixLinearBranching()`](launcher/internal/gitman/gitman.go:378)

**场景**：当所有 commit 在同一 lane 上线性排列（git graph 不产生分支），但实际有多个分支 ref 时，视觉上无法区分分支。

例如 `A(main) → B → C → D → E(0.2.3)` 全在 lane 0。

**修复逻辑**：
1. 从下往上扫描，找出第一个非主分支的 commit（第 400-423 行）
2. 将该 commit 及以上的所有节点移到新 lane（第 427-431 行）
3. 添加一条 fork 线段连接原 lane 和新 lane（第 434-438 行）
4. 在新 lane 上补充竖线（第 441-455 行）
5. 移除被取代的旧 lane 竖线（第 458-465 行）

### 6. 返回数据 [`DualGraphOutput`](launcher/internal/gitman/gitman.go:340)

```json
{
  "graph": {
    "max_lane": 2,
    "rows": 50,
    "nodes": [
      { "row": 0, "lane": 0, "sha": "abc123...", "message": "...", "color": "#F4A261", "refs": ["HEAD -> main"] },
      { "row": 1, "lane": 1, "sha": "def456...", "message": "...", "color": "#4CAF50", "refs": ["0.2.3"] }
    ],
    "segments": [
      { "from_lane": 0, "to_lane": 1, "row": 1, "type": "fork", "color": "#F4A261" }
    ]
  },
  "working_head": "abc123..."
}
```

## 二、React 前端：SVG 渲染层 [`launcher/frontend/src/components/GitGraphCanvas.tsx`](launcher/frontend/src/components/GitGraphCanvas.tsx)

### 1. 布局常量（第 4-12 行）

| 常量 | 值 | 含义 |
|------|-----|------|
| `ROW_H` | 32 | 每行高度 |
| `LANE_W` | 24 | 每 lane 宽度 |
| `DOT_R` | 5 | 普通 commit 圆点半径 |
| `HEAD_R` | 8 | HEAD commit 圆点半径 |
| `PAD_L` | 16 | 左侧内边距 |
| `PAD_T` | 16 | 顶部内边距 |
| `MSG_X` | 280 | commit message 的 X 坐标 |
| `BADGE_GAP` | 4 | ref 标签间距 |
| `BADGE_H` | 16 | ref 标签高度 |

### 2. 坐标映射函数（第 42-43 行）

```typescript
const y = (row: number) => PAD_T + row * ROW_H;  // 行号 → Y 坐标
const x = (lane: number) => PAD_L + lane * LANE_W + LANE_W / 2;  // lane 号 → X 坐标
```

### 3. SVG DOM 结构（第 47-127 行）

#### 第一层：线段 [`<line>`](launcher/frontend/src/components/GitGraphCanvas.tsx:49-61)

遍历 `segments[]`，每条线段绘制一个 `<line>`：

```tsx
<line
  x1={x(seg.from_lane)} y1={y(seg.row - 1)}
  x2={x(seg.to_lane)}   y2={y(seg.row)}
  stroke={seg.color} strokeWidth={2} opacity={0.7}
/>
```

- vline：`from_lane === to_lane`，竖直线
- fork：`from_lane < to_lane`，从左上到右下斜线
- merge：`from_lane > to_lane`，从右上到左下斜线

#### 第二层：节点 [`<g>`](launcher/frontend/src/components/GitGraphCanvas.tsx:64-126)

每个 commit 节点包含：

**a) HEAD 光环**（第 72-78 行）—— 如果 `n.sha === working_head`，画一个绿色外圈：
```tsx
<circle cx={cx} cy={cy} r={HEAD_R + 3} fill="none" stroke="#4CAF50" opacity={0.6} />
```

**b) Commit 圆点**（第 79-86 行）—— 可点击，点击切换 tooltip：
```tsx
<circle
  cx={cx} cy={cy} r={isHead ? HEAD_R : DOT_R}
  fill={n.color}
  stroke={isHead ? '#4CAF50' : '#fff'}
  strokeWidth={isHead ? 2.5 : 1.5}
  onClick={() => setTooltip(...)}
/>
```

**c) HEAD 标签**（第 88-96 行）—— 绿色 "HEAD" 文字

**d) 分支 ref 标签**（第 98-119 行）—— 彩色圆角矩形 + 分支名，排在 commit message 之前

**e) Commit message**（第 121-123 行）—— 单行显示，超过 80 字符截断加 `…`

### 4. Tooltip 弹窗（第 130-183 行）

点击 commit 圆点触发，固定定位在屏幕中央，显示：
- SHA（前 8 位，金色 monospace）
- 分支 ref 列表（彩色标签）
- 完整 commit message
- 作者 + 日期
- **"回档到该版本"按钮**（第 167-179 行）—— 调用 `onCheckout(tooltip.sha)` 触发 Go 端的 `GitDualCheckout`

## 三、完整调用链路

```
用户点击「版本」tab
       │
GitManager.tsx 加载
       │
GitDualGraph(500) ──Wails──→ App.GitDualGraph()
                                   │
                          GetStructuredGraph()  ← git log --graph --all
                                   │
                          GetHeadSHA()        ← git rev-parse HEAD
                                   │
                          DualGraphOutput { graph, working_head }
                                   │
GitGraphCanvas.tsx 收到数据
       │
  SVG 渲染：
    1. segments.map → <line>（竖线/分叉/合并）
    2. nodes.map → <g>（光环 + 圆点 + HEAD标签 + ref标签 + message）
    3. tooltip 弹窗（含回档按钮）
```

## 四、核心设计要点

1. **前后端分离**：Go 端负责所有 git 命令和拓扑解析，前端只做纯渲染，零逻辑
2. **颜色确定性**：通过分支名哈希确定颜色，同一分支跨会话保持颜色一致
3. **线性链修复**：`fixLinearBranching` 解决了 `git log --graph` 在单分支线性场景不产生分叉图形的视觉缺陷
4. **双仓库支持**：`DualGraphOutput` 的 `working_head` 字段标记"可变仓库"的 HEAD 位置，在基准仓库的 graph 上用绿色光环标注，实现双仓库回档架构（基准仓库只读 + 可变仓库可重置）

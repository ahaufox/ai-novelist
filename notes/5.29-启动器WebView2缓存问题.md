# 启动器 WebView2 缓存问题

## 现象

- 启动器（Wails）的 WebView（内嵌 `<iframe>`）访问 `localhost:3000` 显示**旧版前端**
- 默认浏览器（Chrome）访问同一个地址显示**新版前端**
- 后端 API 返回的数据是正确的，说明后端没问题

## 根因

Wails 在 Windows 上使用 **WebView2**（Edge Chromium）作为渲染引擎。WebView2 **拥有完全独立于系统浏览器的缓存空间**，包括：

- 独立的 HTTP 缓存（Cache）
- 独立的 Code Cache（JS 缓存）
- 独立的 Local Storage / Session Storage
- 独立的 Service Worker 注册

因此，即使在 Chrome 中按 F12 清缓存、硬刷新，WebView2 的缓存纹丝不动，仍然会从自己的缓存中读取旧版 `index.html`、`.js`、`.css` 等资源。

## 架构

```
你的项目 frontend/          (新版代码)
    ↓ npm run dev
Vite dev server :3000       (服务新版资源)
    ↓
Chrome 访问 :3000           → ✅ 新版 (Chrome 自己的缓存)
Wails WebView2 访问 :3000   → ❌ 旧版 (WebView2 自己的缓存)
```

## WebView2 缓存位置

实测路径：

```
C:\Users\denghuo\AppData\Roaming\qingzhu-launcher.exe\EBWebView\Default\Cache
```

WebView2 的缓存目录结构（`%APPDATA%\qingzhu-launcher.exe\EBWebView\Default\`）：

| 目录 | 用途 |
|------|------|
| `Cache` | HTTP 资源缓存（最重要的缓存目录） |
| `Code Cache` | JavaScript 编译缓存 |
| `Local Storage` | localStorage 数据 |
| `Session Storage` | sessionStorage 数据 |
| `GPUCache` | GPU 着色器缓存 |
| `Service Worker` | Service Worker 脚本缓存 |

## 解决方案

### 方案一：Vite 禁止缓存（治本 ✅ 已执行）

修改 `frontend/vite.config.ts`，给 Vite dev server 的每个响应添加禁止缓存的 HTTP 头：

```ts
server: {
  port: 3000,
  headers: {
    'Cache-Control': 'no-store, no-cache, must-revalidate, proxy-revalidate',
    'Pragma': 'no-cache',
    'Expires': '0',
  },
  // ... 其余配置
}
```

原理：Vite dev server 在每次请求的响应头中明确告诉 WebView2 "不要缓存我"。**重启前端服务后生效，之后不会再出现缓存问题。**

### 方案二：手动清 WebView2 缓存（治标）

如果已经缓存了旧版资源，需要手动删除：

1. 打开文件资源管理器
2. 地址栏粘贴：`C:\Users\denghuo\AppData\Roaming\qingzhu-launcher.exe\EBWebView\Default\Cache`
3. `Ctrl+A` 全选 → 右键删除
4. 重启启动器

或者更彻底地删除整个 `EBWebView` 目录：
`C:\Users\denghuo\AppData\Roaming\qingzhu-launcher.exe\EBWebView`

### 方案三：启用 WebView2 DevTools（排查用）

修改 `launcher/my.go` 添加 Debug 配置后重新编译启动器：

```go
Debug: options.Debug{
    OpenInspectorOnStartup: true,
},
```

编译后可用 F12 打开 DevTools，在 Network 面板查看哪些资源命中了缓存。
